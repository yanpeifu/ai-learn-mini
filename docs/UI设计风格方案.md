## 0. 三件必须先拍板的事（已确认）

**确认结果（2026-09-15）**：

1. **版权** → 同意不直接使用《阿衰》的任何形象，改做原创吉祥物。
2. **语气** → 同意取"怀旧与幽默"、不取"幼稚"。
3. **深色模式** → 同意 MVP 只做浅色模式。

以下保留原始分析，供后续回顾与对外说明。

### 0.1 版权：只借鉴"画风"，不使用《阿衰》的任何具体形象

《阿衰》是猫小乐（陈乐）的原创作品，角色形象、名字、分镜语言都受著作权保护。
**我们不能在小程序里使用阿衰、大脸妹、金老师等任何具体角色**，
也不能使用其标志性造型的近似变体。

可以合法借鉴的是**视觉语言层面**的东西：

| 可以借鉴（画风层面） | 不能使用（作品层面） |
| --- | --- |
| 粗黑描边的硬笔线条 | 阿衰的具体人物形象与外貌特征 |
| 高饱和平涂的块面色彩 | 角色的名字、口头禅、经典台词 |
| 夸张的表情演出 | 原作的具体画面、分镜、构图 |
| 校园日常的轻松幽默感 | 任何与原作角色高度相似的"致敬款"设计 |

**所以方案是**：我们做一套**原创的吉祥物与插画体系**，用"阿衰式"的线条与表情语言，
讲我们自己的故事。这样既拿到了那种感觉，又不会有法律风险。

### 0.2 语气校准：要"幽默"，不要"幼齿"

《阿衰》的核心读者语境是**校园搞笑**，而我们的目标用户是
**大学生与考公考编人群（22–32 岁）**。这里存在一个真实的张力：

> 照搬阿衰的"中二学生气"，会让成年备考用户觉得产品幼稚、不专业。

**我的建议是取"怀旧与幽默"，不取"幼稚"**：

| 取 | 不取 |
| --- | --- |
| "当年上课偷偷看漫画"的那份会心一笑 | 卡通字体满屏、叠字卖萌（"题目超简单哒~"） |
| 幽默的错题吐槽、有梗的加载文案 | 幼稚的角色对白、奶声奶气的语音 |
| 手绘线条的松弛感、纸张质感 | 幼儿园式的彩虹色与气球装饰 |
| 努力被看见的温暖反馈 | 过度亢奋的街机式特效 |

一句话概括：**它是一个"陪你备考的朋友"，不是"哄小孩的玩具"。**

### 0.3 是否需要深色模式？

风格本身（黏土拟态 + 手绘线条）在深色模式下会失去纸张和手绘的质感，
且备考用户多为白天碎片时间使用。**建议 MVP 只做浅色模式**，
深色模式放到 V1.0 再评估。如果一定要做，需要重新调一套低饱和深色底，不是简单反色。

## 1. 参考调研：市面上同类产品的设计语言

在定风格之前，我调研了同类产品和当前的色彩趋势。

### 1.1 同类产品的设计语言

| 产品 | 设计语言 | 可借鉴 | 不借鉴 |
| --- | --- | --- | --- |
| **多邻国 Duolingo** | 高饱和但克制；扁平插画 + 强游戏化；关卡路径、连胜、排行榜；动效与音效灵动；IP 形象贯穿全程 | 关卡地图的进度可视化、答题微交互、IP 的情绪陪伴感 | 过强的"上瘾"机制（对我们这类知识学习场景会显得刻意） |
| **粉笔** | 工具理性、信息密度高、蓝灰主色；以题库和效率为核心 | 答题页的信息层级与操作效率 | 冷峻的工具感——它与我们要的"治愈"相冲突 |
| **作业帮** | 绿白配色、界面活泼、功能入口密集 | 活泼的配色倾向 | 入口过密的首页（我们要克制） |
| **小猿搜题** | 蓝白简洁、界面清爽 | 单任务聚焦的页面结构 | 过于中性的视觉个性 |

**结论**：同类产品要么**冷峻高效**（粉笔），要么**功能堆叠**（作业帮），
要么**强游戏化**（多邻国）。**"温暖、有手绘感、像一本会陪你学习的漫画书"这个位置是空的。**
这正是我们的机会。

### 1.2 2026 年的色彩趋势

调研显示，2026 年的色彩趋势以**"柔性力量对抗焦虑"**为主线：
**低饱和、治愈系色彩成为主流**，情绪价值成为核心驱动力；
色彩上强调"低攻击性、高包容度，用色彩给情绪松绑"，
柔和的雾感玫瑰、数字薰衣草、云上舞白等色系受到青睐。

这与我们想要的方向完全一致——**备考本身就是高焦虑场景，
界面不应该再给用户施加压力**。

### 1.3 风格基线（来自设计系统库）

我用设计系统检索工具跑出的基线是 **Claymorphism（黏土拟态）**：

| 特征 | 参数 |
| --- | --- |
| 关键词 | 软 3D、圆润饱满、玩具感、泡泡感、粗描边 3–4px、内外双层阴影、圆角 16–24px |
| 最适合 | 教育类应用、儿童应用、创意工具 |
| 代表色 | 柔和的马卡龙色（蜜桃、婴儿蓝、薄荷、淡紫） |
| 动效 | 柔和回弹 cubic-bezier(0.34, 1.56)、200ms 软按压 |
| 性能成本 | 低（纯 CSS 可实现） |

**这个基线与"阿衰的漫画感"高度互补**，两者叠加就是我们的风格。

## 2. 风格定位：漫画黏土风（Comic Clay）

### 2.1 一句话定义

> **用漫画的线条，包住黏土的柔软，涂上治愈的颜色。**

### 2.2 三个来源的融合

| 来源 | 贡献什么 | 具体表现 |
| --- | --- | --- |
| **《阿衰》的画风语言** | 线条与幽默感 | 粗黑描边、硬笔平涂、夸张表情、轻松吐槽 |
| **黏土拟态 Claymorphism** | 形体与手感 | 圆润饱满的圆角、双层阴影、按一下会"陷下去"的物理感 |
| **2026 治愈系色彩** | 情绪基调 | 低攻击性的暖色纸感底、柔和的成功/失败色、不发光的柔和点缀 |

### 2.3 风格识别度：三个"签名动作"

一个风格要能被一眼认出来，必须有几个固定动作。我们定三个：

1. **所有卡片和按钮都有 2.5–3px 的墨黑描边**（漫画感来源）
2. **阴影不是模糊的灰色，而是向下偏移 4px 的纯色硬投影**（印刷/漫画感），
   按压时投影收为 0、元素下沉 3px（黏土手感）
3. **每张卡片左上角有一点柔和的内部高光**（黏土的"捏出来"的质感）

这三条组合起来，就是我们的视觉签名。

## 3. 色彩系统

### 3.1 主色板

| 角色 | 色值 | 用途 | 备注 |
| --- | --- | --- | --- |
| 纸张底 | `#FFFCF7` | 页面背景 | 更暖更淡，纸的质感 |
| 卡片 | `#FFFFFF` | 卡片、弹窗 | |
| **墨线** | `#33302E` | 所有描边、主文字 | 暖调深灰，比纯黑柔和 |
| **暖阳橙** | `#FFA85C` | 主按钮、进度条、品牌色 | 降饱和后的蜜桃橙 |
| 暖阳橙·按压 | `#EE9247` | 按钮按下态 | |
| **薄荷绿** | `#7ED9A8` | 答对、掌握、成长 | 柔和不刺眼 |
| 薄荷绿·深 | `#2A7D57` | 绿色系文字 | 对比度达标 |
| **珊瑚红** | `#FF9A9A` | 答错选项填充 | 柔和，不带压迫感 |
| 珊瑚红·深 | `#C4564F` | 错误文字（配白字 4.8:1） | |
| **薰衣草紫** | `#B9A6F5` | 星级、稀有奖励、成就 | 呼应 2026 治愈色 |
| 暖黄 | `#FFE08A` | 引导问题、提示条 | |
| 次级文字 | `#8A8078` | 说明文字 | |
| 分隔线 | `#F0E9E0` | 分隔 | |

### 3.2 关键的对比度规则（重要）

**橙底白字是不合格的。** `#FFFFFF` 在 `#FFA85C` 上只有约 2:1 对比度，远低于 4.5:1 标准。

正确做法是**橙底 + 墨黑字**（约 7:1）——这恰好也是漫画的经典配色，
明亮底色配粗黑文字，识别度和风格感同时成立。

| 组合 | 对比度 | 是否可用 |
| --- | --- | --- |
| 墨黑字 / 暖阳橙底 | ≈ 6.8:1 | ✅ 主按钮、进度 |
| 墨黑字 / 薄荷绿底 | ≈ 7.6:1 | ✅ 答对反馈 |
| 墨黑字 / 暖黄底 | ≈ 9.5:1 | ✅ 提示条 |
| 墨黑字 / 纸张底 | ≈ 13:1 | ✅ 正文 |
| **白字 / 暖阳橙底** | ≈ 2.0:1 | ❌ 禁止 |
| **白字 / 珊瑚红底** | ≈ 3.0:1 | ❌ 禁止；改用 `#C43D3D` 底配白字（4.8:1） |

### 3.3 色彩的情绪分工

| 状态 | 情绪目标 | 用色 |
| --- | --- | --- |
| 答对 | 被肯定、想继续 | 薄荷绿（不是刺眼的荧光绿） |
| 答错 | **不羞辱、被鼓励** | 珊瑚红（不用正红——正红带有"错误/禁止"的压迫感） |
| 连胜 / 通关 | 成就感 | 暖阳橙 + 薰衣草紫 |
| 加载 / 等待 | 安心、不焦虑 | 纸张底 + 手绘进度条 |

**关于答错用色**：这是最容易做错的地方。多数产品用正红 + 大叉号，
对备考用户是二次打击。我们用**珊瑚红 + 手绘小表情 + "这题有点绕"的文案**，
传达的是"没关系，我们来看看为什么"。

## 4. 字体与文字规范

### 4.1 一个必须避开的坑：不要用中文网络字体

设计系统库推荐的 Baloo 2 / Comic Neue 是**拉丁字体**，不包含中文字形。
而中文字体包通常有 3–10MB，**小程序主包限制 2MB**，直接引入会导致无法上线。

**所以中文必须用系统字体**，通过 `font-family` 回退链实现：

```css
font-family: "PingFang SC", "HarmonyOS Sans SC", "MiSans",
             "Source Han Sans SC", "Microsoft YaHei", sans-serif;
```

**唯一的例外**：Logo、数字、以及极少量标题字可以用特殊字体，
但必须**做字形子集化**（只保留用到的几十个字），控制在 100KB 以内。

### 4.2 字号规范

| 层级 | 字号 / 行高 | 字重 | 用途 |
| --- | --- | --- | --- |
| 展示级 | 40px / 1.2 | 700 | 结算页正确率大数字 |
| 大标题 | 28px / 1.3 | 700 | 页面主标题 |
| 标题 | 20px / 1.4 | 600 | 卡片标题 |
| 正文 | 16px / 1.6 | 400 | 题干、讲解 |
| 辅助 | 14px / 1.5 | 400 | 说明、时间 |
| 最小 | 12px / 1.4 | 400 | 标签、角标（**不再更小**） |

### 4.3 数字的特殊处理

得分、正确率、用时这类数字是"成就感载体"，建议使用**等宽或圆润的显示型数字字体**
（如 Baloo 2 的数字、或系统字体的 tabular-nums），并加大字重。

## 5. 形状、描边与阴影（风格核心）

### 5.1 圆角

| 元素 | 圆角 |
| --- | --- |
| 卡片、弹窗 | **24px** |
| 按钮 | **18px**（大按钮可用胶囊 999px） |
| 输入框 | 18px |
| 选项条 | 16px |
| 小标签 / 角标 | 12px |
| 头像 / 吉祥物容器 | 圆形 |

### 5.2 描边

- 统一 **2.5px** 实线（治愈向已从 3px 调细）
- 颜色统一 `#33302E`
- **不要用描边过细**——描边是"漫画感"的全部来源，细了就变成普通卡片

### 5.3 阴影（三层叠加）

```css
/* 1. 硬投影：漫画感来源（治愈向已从 4px 收到 2px） */
box-shadow: 0 2px 0 #33302E;

/* 2. 柔和外扩散：让元素微微离开纸面 */
box-shadow: 0 2px 0 #33302E, 0 10px 20px rgba(51, 48, 46, 0.06);

/* 3. 内部高光：黏土手感 */
box-shadow: 0 2px 0 #33302E, 0 10px 20px rgba(51,48,46,.06),
            inset 0 2px 0 rgba(255, 255, 255, 0.65);
```

### 5.4 按压反馈（风格签名动作）

```css
/* 默认 */
transform: translateY(0);   box-shadow: 0 2px 0 #33302E;

/* 按下：影子收掉、元素下沉，模拟真的按了下去 */
transform: translateY(2px); box-shadow: 0 0 0 #33302E;
transition: 120ms cubic-bezier(0.34, 1.56, 0.64, 1);
```

**这个"按下去"的反馈是整个设计里最重要的一处手感**，
它把"点击一个按钮"变成了"按压一个实体"。

## 6. 组件规范

### 6.1 按钮

| 类型 | 外观 | 用途 |
| --- | --- | --- |
| 主按钮 | 暖阳橙底 + 墨黑描边 + 墨黑文字 + 硬投影 | 开始生成、开始闯关 |
| 次按钮 | 白底 + 墨黑描边 + 墨黑文字 | 重新生成、返回 |
| 危险按钮 | 珊瑚红深色底 + 白字 | 删除、退出 |
| 文字按钮 | 无底无描边 + 下划线 | 跳过、稍后再说 |

- 高度：大按钮 52px，常规 44px（**不小于 44px，满足触控最小尺寸**）
- 禁用态：透明度 40% + 去掉硬投影 + 不可点击

### 6.2 卡片

- 白底 + 20px 圆角 + 3px 墨黑描边 + 三层阴影
- 内边距 16px
- 卡片之间间距 12px

### 6.3 选项条（答题页最重要的组件）

| 状态 | 外观 |
| --- | --- |
| 默认 | 白底 + 墨黑描边 + 硬投影；左侧圆形字母标 A/B/C/D |
| 已选中 | 暖黄底 + 描边加粗 3.5px + 下沉 2px |
| 答对 | 薄荷绿底 + 右侧弹出对勾（弹入动画） |
| 答错（自己选的） | 珊瑚红底 + 左右轻晃一次 + 左侧小表情 |
| 答错（正确答案） | 薄荷绿描边高亮 + "正确答案"角标 |
| 禁用 | 透明度 50%，不再响应点击 |

**注意**：答错时**正确答案和用户的错误答案要同时可见**，
这是"教学"而不是"评判"的关键设计。

### 6.4 进度条

- 高度 12px，圆角 999px，墨黑描边 2px
- 填充色暖阳橙，**填充末端画一个小小的手绘进度标记**（如一个正在爬的小人）
- 关卡完成时，整条进度条有一次快速的"唰"的填充动画

### 6.5 弹窗与提示

- 圆角 24px，白底，墨黑描边，硬投影
- 左上角放一个吉祥物小表情（按场景切换：疑问/加油/庆祝）
- 按钮固定在底部，主次分明

## 7. 插画与角色设定

### 7.1 吉祥物（原创，必须做）

一个贯穿全程的"学习搭子"。建议设定：

| 属性 | 设定 |
| --- | --- |
| 形态 | 圆滚滚的橘色小团子，头顶一撮呆毛 |
| 五官 | 两点式眼睛 + 一条弧线嘴巴（**表情全靠眉毛和嘴型变化**，这是阿衰式夸张演出的简化版） |
| 身体 | 没有明显四肢，靠整体形变表达动作（好画、好动效、好传播） |
| 配色 | 与主色一致的暖阳橙 + 墨黑描边 |
| 名字 | **待你确认**（见第 12 节） |

**设计上的取舍**：不画复杂的手脚和服装。
一是降低插画成本（一人开发不可能画大量精细插画），
二是圆形角色在任何尺寸下都清晰，适合小程序的小图标场景。

### 7.2 表情包（8 个，覆盖全流程）

| 场景 | 表情 |
| --- | --- |
| 首页等待输入 | 期待（眼睛发亮） |
| 生成中 | 认真（眯眼专注） |
| 答对 | 惊喜（星星眼） |
| 答错 | 挠头（不好意思） |
| 引导问题 | 思考（歪头） |
| 连对 | 欢呼 |
| 通关 | 庆祝（撒花） |
| 空状态 | 探头（"这里还没有内容哦"） |

### 7.3 背景与质感

- 页面背景不用纯色，叠加**极淡的手绘点阵/斜线纹理**（透明度 3–5%），营造纸张感
- 重要区块可用**撕纸边、胶带贴角**这类小元素点缀，但**每页最多一处**，否则会显得杂乱

## 8. 图标规范

- 统一使用**线性图标 + 2px 描边 + 圆头端点**，与粗线条风格一致
- 图标库建议：Phosphor Icons（描边风格最接近）或 Lucide
- **禁止用 emoji 作为功能图标**（不同设备渲染不一致，也无法控制风格）
- 尺寸令牌：`icon-sm 20px` / `icon-md 24px` / `icon-lg 32px`

> 注：吉祥物的表情、以及"加油""撒花"这类**情绪性内容**可以用插画表达，
> 但**导航、设置、返回这类功能性图标必须用矢量图标**。

## 9. 动效与音效

### 9.1 动效原则

| 原则 | 具体 |
| --- | --- |
| 弹性但不浮夸 | 统一缓动 `cubic-bezier(0.34, 1.56, 0.64, 1)` |
| 时长克制 | 按压 120ms，弹入 280ms，页面转场 300ms |
| 退出快于进入 | 撤场动画约为入场的一半时长 |
| 尊重系统设置 | 必须支持 `prefers-reduced-motion`，开启时改为淡入淡出 |

### 9.2 关键动效清单

| 场景 | 动效 |
| --- | --- |
| 按钮按下 | 下沉 4px + 投影收为 0 |
| 选择选项 | 选项轻微放大 1.03 + 描边加粗 |
| 答对 | 选项变绿 + 对勾从中心弹出 + 吉祥物表情切换 |
| 答错 | 选项左右轻晃两次（**不超过 300ms**）+ 正确答案高亮 |
| 提交后展示讲解 | 卡片从下方滑入 + 内容逐行淡入 |
| 连对 3 题 | 连击数字放大弹跳 + 进度条一次加速脉冲 |
| 关卡完成 | 星星依次弹出（间隔 120ms） |
| 页面转场 | 横向滑入（模拟翻页） |

### 9.3 音效

| 场景 | 音效 |
| --- | --- |
| 答对 | 木琴/马林巴的清脆单音 |
| 答错 | 柔和的"噗"声（**绝不用蜂鸣器式的刺耳失败音**） |
| 连对 | 音阶上行 |
| 通关 | 一小段欢快的完整旋律 |

**三个实现注意点**：

1. 首次播放音效**必须由用户交互触发**，否则会被系统静默拦截——
   建议在用户第一次点击"开始生成"时预加载全部音效
2. 必须**处理手机静音键状态**，静音时不要强制播放
3. 音效音量要低于系统媒体音量，学习场景下不应该吓到用户

## 10. 文案语气

风格不只体现在视觉上，**文案是最容易被忽略但感受最强烈的一环**。

### 10.1 语气三原则

| 原则 | 说明 |
| --- | --- |
| **说人话** | 不用"系统繁忙，请稍后重试"，用"网络打了个盹，再试一次？" |
| **不指责** | 判错不说"回答错误"，说"这题有点绕，来看看为什么" |
| **有分寸** | 可以幽默，但不卖萌过度；用户是来备考的成年人 |

### 10.2 关键文案对照表

| 场景 | ❌ 常见写法 | ✅ 我们的写法 |
| --- | --- | --- |
| 加载中 | 加载中… | 正在把你的笔记拆成知识点… |
| 生成超时 | 请求超时 | 想得有点久，要不再试一次？ |
| 答错 | 回答错误 | 这题有点绕，我们来看看 |
| 连续答错 | 正确率偏低 | 别急，这块本来就不好啃 |
| 通关 | 恭喜完成 | 通关！这一关你用了 6 分 12 秒 |
| 空状态 | 暂无数据 | 这里还空着，去闯第一关吧 |
| 网络错误 | 网络异常 | 网络打了个盹，点一下重试 |
| 引导问题 | 提示 | 再想一下：如果……会怎样？ |
