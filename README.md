# ai-learn-mini

AI 闯关学习小程序 —— 把任意一段知识，变成一条游戏化的学习路径。

> 当前阶段：**需求确认完成，正在进行「出题质量」的技术验证。**
> 还没有开始写小程序前端代码，这是有意为之：先验证最危险的假设。

---

## 为什么先写质量检测脚本

这个产品的核心假设是「AI 自动生成的题目质量足够好」。如果这个假设不成立——
比如答案经常错、选项模棱两可、题目重复——那么后面做的所有前端、动画、
分享功能都没有意义。

所以第一步是把「输入一段文字 → 输出一套题」跑通，并且**用可量化的方式**
评估质量，而不是凭感觉看两眼。

## 快速开始

### 1. 离线自检（不需要 API Key，先跑这个）

```bash
cd E:\CodexProjects\ai-learn-mini
python quality_check.py --mock
```

它会用内置的两份模拟数据跑一遍：

- 一份**故意包含 10 类缺陷**的数据 → 检查器应该报出大量错误
- 一份**干净的数据** → 检查器应该给出满分、零误报

如果输出符合上面的预期，说明脚本本身工作正常。

### 2. 配置 API Key

脚本会**自动读取项目根目录的 `.env` 文件**（其次读当前工作目录的 `.env`）。
所以最简单的做法是编辑 `.env`：

```powershell
notepad .env
# 把 DEEPSEEK_API_KEY=sk-替换成你自己的key
# 改成 DEEPSEEK_API_KEY=sk-你的真实key
```

也可以用环境变量（**优先级高于 `.env`**）：

```powershell
# 当前会话有效
$env:DEEPSEEK_API_KEY = "sk-你的key"

# 永久写入用户环境变量
[Environment]::SetEnvironmentVariable("DEEPSEEK_API_KEY", "sk-你的key", "User")
```

可选变量：

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `DEEPSEEK_API_KEY` | 无 | 必填。也支持 `LLM_API_KEY`、`API_KEY` 两个别名 |
| `LLM_BASE_URL` | `https://api.deepseek.com` | 兼容 OpenAI 格式的接口地址 |
| `LLM_MODEL` | `deepseek-flash` | 模型名 |
| `LLM_TIMEOUT` | `180` | 单次请求超时（秒） |

运行时会打印脱敏后的配置信息，方便你确认读到的是哪个文件、哪把 Key：

```
[配置] 已加载 .env：E:\CodexProjects\ai-learn-mini\.env
[配置] API Key：sk-1a2******5o6p
```

### 3. 真实调用

```bash
# 先跑 3 个样例试水，确认配置正确、成本可控
python quality_check.py --limit 3

# 跑完整的 20 个跨领域样例
python quality_check.py

# 用自己的知识文本
python quality_check.py --text "光合作用是植物利用光能……"
python quality_check.py --file 我的笔记.txt

# 只看会发给模型的提示词，不产生费用
python quality_check.py --dry-run
```

### 4. 看报告

报告写在 `reports/` 下：

- `quality_report_<时间戳>.md` —— 人工阅读，含得分、问题清单、改进建议
- `raw_<时间戳>.json` —— 原始生成结果，便于逐题人工核对

## 12 类自动检查项

| 检查项 | 级别 | 含义 |
| --- | --- | --- |
| `answer_not_in_options` | 错误 | 答案不在选项里 —— 用户永远答不对 |
| `option_text_dup` | 错误 | 存在完全相同的选项 —— 题目没有唯一解 |
| `option_low_quality` | 错误 | 使用了「以上都对」这类无效干扰项 |
| `judge_option_count` | 错误 | 判断题的选项数不是 2 |
| `single_option_count` | 错误 | 单选题的选项数不是 4 |
| `answer_count_mismatch` | 错误 | 单选/判断给了多个答案，或多选只给一个 |
| `explanation_answer_mismatch` | 错误 | 讲解里**断言**答案是 C，`answer` 字段却是 A |
| `stem_duplicate` | 错误 | 两道题题干相似**且选项重合**，基本是同一道题 |
| `kp_ref_invalid` | 错误 | 题目关联的知识点不存在 |
| `explanation_too_short` | 警告 | 讲解过短，教学价值不足 |
| `answer_skew` | 警告 | 单选题答案集中在同一个选项 |
| `difficulty_flat` | 警告 | 所有题难度相同，构不成「闯关」 |
| `kp_uncovered` | 警告 | 有知识点没有出题 |
| `option_set_duplicate` | 警告 | **3 道及以上**题目使用完全相同的选项组 |
| `generation_failed` | 错误 | 模型返回无法解析为 JSON（会自动重试 2 次） |

评分规则：满分 100，每个错误扣 8 分，每个警告扣 3 分。

### 刻意不做的检查（重要）

下面三种情况看起来像缺陷，其实是**优秀的出题设计**。检查器刻意不报，
否则会把你引向"修改并没有坏的地方"。

**1. 不检查「选项之间是否高度相似」。**
只差一两个字的"最小对照选项"（例如把「光密射向光疏」改成「光疏射向光密」）
用于考察精确理解，是好的干扰项。用相似度去判会把好题误判成缺陷。

**2. 不把「句式相同的并列出题」当重复。**
「求基期量的公式是？」与「求增长量的公式是？」句式几乎一样，
但考察的是不同知识点，便于对比记忆。只有当题干相似**且选项也重合**时，
才算真正的重复题。

**3. 不把「解释错误选项」当答案不一致。**
讲解里写「故不选D」「若选B则与原文相反」，是在解释错误选项错在哪，
属于标准教学写法。只有讲解**断言**正确答案（如「正确答案应为 A、B、C」）
与 `answer` 字段冲突时，才判定为不一致。

自动检查只能发现**结构性缺陷**。题目在事实上是否准确、是否存在歧义、
是否符合原文，仍然需要人工抽检——这是脚本替代不了的部分。

---

## 改了检查规则之后怎么验证

调整检查规则后，**不需要重新花钱调用大模型**。用 `--reaudit` 对上次的
原始结果重新评分即可：

```bash
python quality_check.py --reaudit reports/raw_20260914_131957.json
```

它会输出新旧得分对比表，并生成一份 `reaudit_*.md` 报告，
明确列出"调整后仍存在的问题"。
